# Этап 3 — связь характеристик и фильтров, 12.11.2026

Опубликовано: private release /home/s/shinaspec/catalog-facet-bridge-20261112. Шесть файлов; контроль версий, lint, резервные копии, атомарная замена. Подтверждение outputs/facet-bridge-publication-verification.json. В существующих товарных, справочных и SEO-таблицах fingerprints до/после совпали; 22 группы дали прежнее число товаров. Созданы только три пустые таблицы настройки/журнала. Автоматических соответствий или включённых связей нет.

Админка: /admin/catalog-facet-bindings, ссылка из справочников. На группу назначается одно простое свойство и точные соответствия исходных значений существующим ID attribute_value этой группы. Для списков используется код варианта, для числа нормализуются только разделитель/ведущие/концевые нули в той же единице. Разные единицы не пересчитываются, текст не объединяется догадкой. Режимы off / preview / active; по умолчанию preview. Изменение действует на все категории, где используется группа; состав/порядок групп остаётся в catalog-display. Существующие alias и canonical не меняются.

Применение: на каждом запросе рассчитывается недеструктивная проекция только из известных, подтверждённых скалярных значений с источником. Полный профиль проходит действующий нормализатор; unclassified пропускается. При отсутствующем/неподтверждённом/противоречивом значении, неподдерживаемом формате или неполной карте сохраняется прежняя группа связей целиком. Для multi_option нужны соответствия всех выбранных значений; частичной подмены нет. Включённая полностью сопоставленная характеристика заменяет старые значения только данной группы. При отключении сразу возвращается старый отбор. attribute_product и product_attribute не переписываются.

Счётчики, OR внутри группы, AND между группами, основной отбор и определение применимой посадочной используют одну проекцию. Связанные посадочные и категории, источник рекомендаций также подключены. Эффективные join-связи при отсутствии подмены используют ровно исходную attribute_product, а при наличии — derived relation старых строк без заменяемых групп плюс подтверждённые пары. Первую медленную предварительную проверку с коррелированным cross-join остановили до установки и заменили на эти соединения. Успешный повтор установки занял около5 секунд. Фасеты категории9 на боевом сервере:6 групп, запросы0.045с, публичная категория HTTP200 и прежний H1.

Предпросмотр показывает полностью сопоставленные товары, отличия старых и новых ID и причины отсутствия соответствия. Недоступные/скрытые цели карты отмечаются отдельно и не применяются. Отображение до100 отличий и100 замечаний. Настройки сохраняются с admin+CSRF, версией связи и версией справочника. Строка не может указывать чужую группу, скрытый ID, дубль канонического значения или неверный код варианта. Лимит200 соответствий; маркер полного получения формы защищает от усечения POST. В журнале остаются состояния до/после и автор.

Проверки: CatalogFacetBridgeDatabaseTest на временных локальных таблицах прошёл preview/active/off, подтверждение/черновики, отсутствие соответствия, полную и неполную многозначность, OR/AND, дисъюнктивные счётчики, посадочные, версии, изоляцию группы и неизменность старых связей. Прошли CatalogFacetsDatabaseTest, CatalogFacetBridgeViewTest, CatalogDictionaryViewTest, CatalogQualityViewTest и CatalogFacetRouteTest.cjs. На сервере проверены6 хешей, рендер новой формы с CSRF/версиями и полными строками, рабочий HTTP-каталог и неизменность существующих таблиц.

Браузерная проверка в этом чате недоступна; серверный рендер не выдаётся за визуальную приёмку. Тестовые соответствия на боевом сервере не создавались. В новой базе пока нет подтверждённых скалярных значений, поэтому включение предполагаемых соответствий не выполнено. Рабочие товары и отложенные замечания не исправлялись.
