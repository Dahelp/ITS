Проверка рабочего сервера

Через SSH выполнен только read-only preflight, переданный на стандартный ввод PHP без сохранения файла на сервере: PHP 8.2.18; MySQL 5.7.21; pdo_mysql и mbstring доступны; product — InnoDB; product.id — int unsigned, первичный ключ. Необходимые старые таблицы присутствуют. Пилотных таблиц нет. Эти проверки подтверждают базовую совместимость, а не заменяют проверку установки и авторизованного HTTP после публикации.

Порядок публикации после разрешения

  1. Повторить preflight; проверить, что пакет не изменился по SHA-256. Проверить отсутствие конфликтующих рабочих файлов; при наличии сравнить содержимое и сохранить копии. Не копировать весь локальный проект.
  2. Снять резервную копию рабочей БД и затрагиваемых файлов в непубличный каталог. Проверить завершение резервирования и доступность копии. Сделать свежий read-only снимок исходных таблиц и сохранить контрольные отпечатки для сравнения.
  3. Разместить файлы во временном непубличном каталоге. Проверить все PHP файлы командой php8.2 -l; сверить хеши. Установщик использует только CREATE TABLE IF NOT EXISTS и заполнение новых справочников. DDL MySQL не откатывается общей транзакцией: при частичной ошибке остановиться и разобрать результат, не объявлять установку успешной.
  4. Сначала разместить только данные app/data/catalog-properties-v1.json, пять сервисов app/services/Catalog*.php из белого списка и два CLI-файла bin/. Контроллер ещё не публиковать. Установить изолированную схему явной командой ниже из корня рабочего проекта: она использует существующие config/config_db.php и vendor/autoload.php. Проверить успешное завершение.
  5. После установки разместить два представления и контроллер по белому списку; контроллер публиковать последним. Новые CLI-файлы не доступны через браузер. Сверить хеши конечных файлов.
  6. Повторить preflight: 12 таблиц, версия 1, до действий редактора 0 профилей товаров и 0 записей истории. Сверить исходные таблицы с контрольными отпечатками: установка не должна их изменить.
  7. Проверить авторизованный раздел /admin/catalog-properties. Неавторизованный посетитель и пользователь без роли admin не должны получать редактор. Проверить 403 при неверном CSRF.
  8. Проверить предпросмотр IT000007251: основной 12-16.5, диаметр 16.5, связь 33x12-20. Простое открытие и предпросмотр не должны создавать профиль или историю.
  9. Первое пробное сохранение — только для IT000007251 в новой базе. Сверить значения и историю, открыть две версии формы и проверить отказ устаревшему сохранению. Затем проверить восстановление прежней версии. Эти действия не должны менять рабочую карточку или YML.
  10. Проверить обычную карточку, каталог, старые SEO-страницы и YML; сравнить исходные таблицы. После успешной проверки добавить одну ссылку на пилот в действующем разделе Яндекс Товары и передать пользователю результат.

Критерии приёмки

  • Доступ только администраторам, корректная работа списка, поиска и редактора.
  • Неизвестные обязательные поля сохраняются как черновик с замечаниями; неподходящие свойства и неизвестные варианты справочника отклоняются.
  • У подтверждённых сведений есть источник; исторические сведения не получают подтверждение автоматически.
  • Основной и взаимозаменяемый размеры не смешаны. Эквивалентность не распространяется на другие товары. Составная маркировка индексов не теряется.
  • Сохранение атомарно, устаревшая версия отклоняется, восстановление записывается в историю.
  • Рабочие таблицы, публичные названия, URL и экспорт не изменены установкой и сохранением в пилоте.

Откат

Если ошибка до открытия редактора — не продолжать публикацию. Если ошибка после публикации — убрать ссылку и контроллер пилота, вернуть прежние версии заменённых файлов из копии; остальные новые файлы можно оставить недоступными до разбора. Новые таблицы и историю не удалять. Публичная витрина от пилотных таблиц не зависит. Ошибочную запись пилота восстанавливать через историю. Полное восстановление рабочей БД без отдельного решения не выполнять: оно может затереть новые заказы, поступившие после резервирования.
