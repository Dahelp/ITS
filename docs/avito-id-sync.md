# Получение номеров новых объявлений Авито

Внутренний `ad_external_id` (например, `its-9328`) остаётся постоянным ID в XML. Присвоенный Авито номер сохраняется отдельно в `avito_id`; нельзя получать его удалением букв из внутреннего кода.

`AvitoIdSync` читает соответствия через GET `/autoload/v2/items/avito_ids`, передавая точные ID из файла. Ответ `null` оставляет запись ожидающей. При следующей проверке появившийся положительный числовой ID сохраняется в БД. Существующие номера не перезаписываются. Ошибки API возвращаются отдельно от результата «номер пока не присвоен».

Кнопки синхронизации товаров и обновления статусов используют этот же механизм без минутного ограничения. В открытом списке `/admin/avito` JS проверяет ожидающие номера при открытии и раз в 60 секунд; после получения номера обновляет таблицу без сброса страницы. Скрытые вкладки приостанавливают запросы. Общий кеш на 60 секунд и блокировка предотвращают одновременные запросы разных вкладок. Автопроверка только получает номера, она не запускает публикацию. Когда список закрыт, отдельного фонового расписания этой правкой не создаётся.

22.10.2026: PHP-тест проверяет последовательность `null → ID`, сохранение, комплект, ошибки 429, ограничение частоты, принудительный ручной запрос и блокировку. JS-тест проверяет таймер, скрытую вкладку, отсутствие параллельных запросов, частичный успех и сохранение страницы таблицы.

Дополнительно на сервере выполнен полный путь `Avito::syncUrlsFromApi()` с живым API и временной копией пяти записей. В копии обнулены номера 240–243, затем восстановлены все четыре реальных номера. У записи 239 Авито по-прежнему возвращает null. Рабочие объявления и их ID этим тестом не изменялись; новые объявления не создавались.

Завершение удаления также проверяется этим минутным циклом. `AvitoDeletion` обрабатывает только записи с `deletion_requested_at`, получает свежий статус напрямую по ID объявления, сохраняет закрытую резервную копию вне public и удаляет локальную запись после подтверждения снятия. При активном статусе или ошибке API запись остаётся. Строки с запросом удаления исключены из XML и из синхронизации legacy-остатков, в том числе при гонке запросов. После удаления таблица перезагружается без сброса страницы. Для №238 (Avito 2476678477) API вернул old; ранее запрошенное пользователем удаление завершено, наличие резервной копии проверено.
