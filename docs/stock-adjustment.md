# Корректировка наличия

29.10.2026 установлено на боевой `its-center.ru`: 14 файлов, исходные значения 1129 товаров и 95 модификаций сохранены, четыре триггера созданы. Проверена поправка −1 в транзакции с откатом; тестовая поправка не сохранена. Главная и каталог вернули HTTP 200. Закрытая серверная копия файлов и снимок исходных остатков: `~/.codex-deploy/stock-adjustment-20261029/`. Посторонние локальные изменения в публикацию не включены.

В карточке товара (добавление, редактирование, копирование) есть целое знаковое поле «Корректировка наличия». При исходном остатке 4 поправка −1 даёт 3. Поправка +4 увеличивает остаток на 4. Значение 0 отменяет поправку. Это постоянная разница, а не команда списания: повторное сохранение −1 не списывает ещё одну единицу. После исправления остатков в учётной системе поправку нужно сбросить в 0.

Для артикулов модификаций есть собственные поправки в строках модификаций. Поправка основного товара относится только к его артикулу, а не распределяется между модификациями.

## Установка

Перед запуском новой версии приложения и кронов выполнить в базе магазина:

```sh
php bin/migrate_stock_adjustment.php
```

Миграция повторяемая. Нужны права ALTER и TRIGGER. Она копирует существующие остатки в исходные поля, добавляет нулевые поправки и создаёт BEFORE INSERT / BEFORE UPDATE триггеры для product и modification. При нулевой поправке количество сохраняется. Перед выкладкой остановить обмены на время установки миграции и новой версии, затем возобновить их. Старые обработчики, пишущие quantity напрямую, нельзя запускать вместе с новой схемой.

## Расчёт и интеграция

- `inventory_quantity` — исходное количество; `inventory_rest` — исходный свободный остаток товара.
- `stock_adjustment` — постоянная поправка. Отрицательные и положительные целые числа, предел ±1000000000.
- `quantity = max(0, inventory_quantity + stock_adjustment)`; `rest = max(0, inventory_rest + stock_adjustment)`.
- Существующие потребители читают итоговые quantity/rest: каталог, поиск, корзина и её повторная проверка, комплекты, аналитика, YML/XML/CSV, остатки Авито. Существующий учёт резервов в этих потребителях сохранён.
- API, пакетный файловый импорт, старые файловые/API кроны, создание и редактирование товаров записывают исходные поля. Триггер пересчитывает итог в той же операции, поэтому повторный обмен не накапливает поправку.
- Файлы InventoryCsvExportService содержат итоговый остаток и два дополнительных столбца `inventory_source_rest` / `inventory_source_quantity` в конце. При обратном импорте исходные значения берутся из этих столбцов, чтобы не вычитать поправку повторно. Исходные файлы 1С без этих столбцов поддерживаются.
- Складские строки `in_stock` и история поступлений сохраняют данные учётной системы: общая поправка сайта не назначает недостачу конкретному складу.
- Сохранение поправки меняет данные сайта сразу. Уже созданные файлы выгрузок и остатки на внешних площадках обновляются при очередном запуске соответствующей выгрузки/синхронизации.

Новые обработчики обмена должны писать `inventory_quantity` / `inventory_rest`, а читать `quantity` / `rest`. Нельзя прибавлять поправку при чтении: она уже учтена базой. Изменение только цены или других атрибутов пересчёт не накапливает.

## Проверка

`php tests/StockAdjustmentDatabaseTest.php` проверяет ввод без базы. Для интеграционных проверок задать `STOCK_TEST_DSN`, `STOCK_TEST_USER`, `STOCK_TEST_PASSWORD`, указывающие на отдельную пустую тестовую MySQL/MariaDB: тест создаёт и удаляет только свои две таблицы, отказывается работать в непустой базе. Проверяются миграция, повторные обновления, отрицательные/положительные поправки, сброс после ограничения нулём, модификации, CSV, корзина, каталог и комплекты.
