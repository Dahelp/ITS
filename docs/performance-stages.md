# Поэтапная оптимизация производительности

## Этап 1: исходная диагностика — 25 ноября 2026

Приложение: собственный PHP MVC (`ishop`, RedBeanPHP), не OpenCart.
Боевой HTTP-ответ сообщает Nginx и PHP 8.2. Это не подтверждает доступ
к конфигурации Nginx или наличие PHP-FPM, Redis и OPcache.

Добавлен CLI-инструмент `bin/measure_ttfb.php`. Пример:

```powershell
C:/xampp82/php/php.exe bin/measure_ttfb.php --runs=5 https://its-center.ru/catalog/shiny https://its-center.ru/category/shiny-dlya-vilochnyh-pogruzchikov
```

Скрипт выполняет последовательные GET с паузой 250 мс, не следует редиректам,
не отправляет формы. Режим anonymous не отправляет cookies. Returning использует
cookies первого запроса к этой странице; это не проверка авторизованного клиента.
Значения cookies и тела ответов не включаются в JSON. Временный cookie jar удаляется.
Учитываются DNS, TCP, TLS, TTFB, полная загрузка, HTTP-статус и заголовки кэширования.
Медиана и p95 считаются только для успешных HTTP 200. При небольшой выборке p95
не является статистически надёжной оценкой. Первый запрос не доказывает холодный
серверный кэш. Внешний TTFB включает сетевые задержки точки измерения.

Подтверждено на production:

Предварительная медиана TTFB (секунды), по три HTTP 200 в каждом режиме:

| Страница | Anonymous | Returning |
|---|---:|---:|
| `/catalog/shiny` | 0,428 | 0,405 |
| `/category/shiny-dlya-vilochnyh-pogruzchikov` | 1,990 | 3,617 |
| `/category/shiny-dlya-vilochnyh-pogruzchikov/6.50-10` | 10,861 | 26,932 |
| Карточка товара, указанная ниже | 2,418 | 1,403 |

Это одна небольшая серия без контроля фоновой нагрузки. Разница режимов
не доказывает, что задержку вызывает именно сессия. Посадочная фильтра —
приоритет для отдельного SQL-профиля. JSON исходных замеров сохранён в
`tmp/ttfb-baseline-2026-11-25.json` и `tmp/ttfb-product-baseline-2026-11-25.json`.

- `/category/shiny` возвращает 301 на `/catalog/shiny`, выдаёт PHPSESSID и no-store.
- `/catalog/shiny` возвращает 200, выдаёт PHPSESSID и
  `Cache-Control: no-store, no-cache, must-revalidate` чистому гостю.
- Карточка `/product/6-50-10-12pr-ttf-qh207-134a5-superguider-shina-dlya-vilochnogo-pogruzchika`:
  по три успешных запроса, медиана TTFB anonymous 2,418 с, returning 1,403 с.
  Чистому гостю каждый раз выдаётся cookie сессии. В обоих режимах — no-store.

Причины в текущем коде:

1. `AppController::__construct()` вызывает `TrafficSource::capture()`, который
   безусловно запускает сессию, даже если bootstrap решил её не запускать.
2. `partials/header.php` запускает сессию и создаёт favorites_csrf для гостя.
3. `layouts/watches.php` запускает сессию перед показом flash-сообщений.
4. `LeadForm::token()` запускает сессию при рендере общих форм и карточки товара.

При первоначальной проверке `its-center.local` не разрешался в DNS. На этапе 2
найден настроенный Apache vhost `its.local`; локальные HTTP-проверки используют
его с явным разрешением в 127.0.0.1.
Старые `tmp/slow.log` и `tmp/slow-db.log` не считаются текущими замерами production.
SQL-время и число запросов на production ещё не измерены.

## Этап 2: реализован и выложен на production — 25 ноября 2026

- `SessionPolicy` управляет запуском сессии и финальными HTTP-заголовками.
  Публичные GET/HEAD без сессии не получают PHPSESSID и по умолчанию отвечают
  `Cache-Control: no-cache` (хранение с обязательной ревалидацией).
  Приватные маршруты, запросы изменения данных, ответы с сессией/Set-Cookie
  и ошибки получают `private, no-store, max-age=0`. Это применяется даже после
  закрытия сессии контроллером и перекрывает случайный public-заголовок.
- Убраны старты сессии из общих шаблонов, создания гостевого favorites_csrf
  и TrafficSource. Удалён неиспользуемый callback_token. `App::on_line()`
  больше не создаёт сессию для проверки отсутствующего пользователя.
- `View::render()` возобновляет только уже открытую в этом запросе сессию,
  если контроллер успел снять блокировку. Это сохраняет flash-сообщения и
  токены авторизованных пользователей, не создавая сессии чистым гостям.
- `POST /session/lead-token` выдаёт токены callback/oneclick без БД.
  До открытия сессии проверяются метод, AJAX-заголовок, Origin/Fetch Metadata
  и разрешённый scope. CORS-разрешения отсутствуют. Ответ всегда no-store.
- Токены запрашиваются при фокусе в форме, открытии модального окна или
  отправке. Запросы разных scope сериализованы, чтобы первый визит не создал
  две сессии. При ошибке/таймауте данные остаются в форме, повтор доступен.
  Сохраняются проверки CSRF, одноразовость, throttle, honeypot и дедупликация.
  Для подготовки токена без JavaScript есть явная ссылка `?lead_form=1`;
  такой запрос создаёт сессию и приватный HTML с noindex, ссылка имеет nofollow.
  Остальные ограничения
  существующих форм без JavaScript (например, модальные окна) не переработаны.
- Источник первого визита фиксируется JS в браузерной session-cookie
  `its_traffic_source` (SameSite=Lax, Secure при HTTPS), без PHP-сессии.
  Сохраняются код источника, путь посадочной, домен реферера и время; полные
  query/referrer не сохраняются. При первом необходимом старте сессии данные
  переносятся в прежнюю структуру. Сервер принимает только три известных
  кода, сам определяет подпись; cookie не используется для прав доступа.
  При отключённом JS остаётся серверная классификация текущего обращения;
  первый визит между анонимными переходами без JS не сохраняется.
- Убрано no-store для статического HTML в Apache. HTML-кэш страниц ещё
  не включён. Необходимо выкладывать PHP, шаблоны и JS одной поставкой.

Также прошли `FavoritesControllerTest.php`, `CartStateTest.php`,
`CheckoutGuestFlowTest.php`, `CheckoutLoginFlowTest.php`, `GuestFavoritesTest.cjs`:
проверки прав/CSRF избранного, состояния корзины, гостевого оформления и входа
с сохранением корзины. PHP lint изменённых PHP-файлов и `httpd -t` — успешно.

HTTP-набор проверяет каталог/категорию, GET/HEAD/301 без cookies, отклонение
неверных token-запросов без сессии, выдачу/повтор токена, разделение scope,
приватный ответ с cookie, подготовку без JS, login и политику catalog-menu.
В браузере проверены сохранение ввода при имитации сетевого отказа и успешный
повтор с реальным локальным endpoint; финальная отправка перехвачена тестом,
заявки/заказы/письма не создавались. Strict UI audit: 0 findings,
`tmp/stage2-premium-audit.json` (статический аудит не заменяет runtime-проверки).

Ограничение: HTTP-проверка конкретной локальной карточки товара сначала
превысила 20 секунд (сервер завершил запрос за 82,561 с), повтор превысил
120 секунд до первого байта. В основной ограниченный HTTP-набор карточка не
включена; доступен явный `--include-product` для отдельной диагностики.
Код карточки проходит PHP lint, а общий tokenField покрыт тестами.
Этот bottleneck требует отдельного профиля на следующих этапах.
После локальной проверки этапы 1–2 выложены на production через защищённое
окружение GitHub Actions. Основная поставка — 18 файлов, дополнительная —
3 файла (шаблон карточки общий для обеих поставок; всего 20 разных runtime-файлов).

Публикации:

- Основная: https://github.com/Dahelp/ITS/actions/runs/45627077816
- Завершающая: https://github.com/Dahelp/ITS/actions/runs/45628523834

Выкладка шла только по manifest, со сверкой SHA-256, lint, приватными резервными
копиями и автоматическим откатом при ошибке установки/HTTP-smoke. Полный rsync,
Composer install и миграции не выполнялись. Механизм отката проверен локально
на принудительном отказе smoke. На production откат не потребовался.

Внешняя проверка обнаружила выдачу `recentlyViewed` в PHP-контроллере карточки.
Она перенесена в `recently-viewed.js`: прежний формат cookie сохранён, срок —
24 часа, история ограничена 30 ID; сервер по-прежнему показывает последние три.
Это убирает Set-Cookie/no-store при обычном GET карточки. Существующие production-
правки остатков в контроллере сохранены: исходный код подтверждён точным хешем
read-only аудита, и в нём заменён только вызов записи cookie.

Итоговые проверки: по 18 реальных HTTP-запросов с сервера и с внешней точки
прошли успешно. Проверены каталог, категория, карточка, HEAD/301 без cookies,
приватные ответы, метод/Origin/scope endpoint, выдача и повтор CSRF, разделение
токенов, подготовка без JS, login, catalog-menu. Заказы, заявки и письма не
создавались. Хеши трёх JS-файлов, полученных с публичного сайта, совпали с
поставкой. Дополнительный `RecentlyViewedClientTest.cjs` также прошёл локально.

Итоговая внешняя медиана TTFB, по три HTTP 200 в каждом режиме:

| Страница | Anonymous, с | Returning, с |
|---|---:|---:|
| `/catalog/shiny` | 0,357 | 0,376 |
| `/category/shiny-dlya-vilochnyh-pogruzchikov` | 1,501 | 1,425 |

Все 24 ответа этой серии — HTTP 200, без Set-Cookie/no-store. Публичный HTML
отвечает `no-cache, max-age=0`; это ревалидация, не включение HTML page cache.
После первого анонимного запроса сервер больше не выдаёт cookies, поэтому
Returning в этой CLI-серии также не содержит PHP-сессии. Отдельная проверка
с настоящей выданной сессией подтвердила `private, no-store, max-age=0`.
Это небольшая серия без контролируемой нагрузки, а не гарантия p95. Цели
TTFB для всей выборки ещё не достигнуты; требуются следующие этапы.

## Этапы 3–7

3. HTML-кэш: разрешённые публичные маршруты, корректный ключ, исключения,
   атомарная запись, защита от stampede и сброс при изменении каталога.
4. Проверка актуальности цен/остатков и отсутствия утечки персональных данных.
5. SQL-профиль, EXPLAIN, существующие индексы, кэш данных; Redis при доступности.
   Без массовой очистки данных и OPTIMIZE TABLE без подтверждённой необходимости.
6. CSS-сборка с сохранением порядка правил, визуальная проверка, LCP/INP/CLS.
7. Анализ sitemap, canonical, robots, параметров, редиректов и логов Googlebot.

Приёмка: категории <0,5 с, подстраницы <0,8 с на согласованной выборке.
HIT/MISS, чистый гость/сессия и нагрузка оцениваются отдельно. Без production
замеров после выкладки достижение целевых значений не заявляется.
