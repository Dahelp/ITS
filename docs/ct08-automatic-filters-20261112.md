# CT-08: автоматическое обновление каталога — опубликовано

Итоговая версия опубликована12.11.2026, проверка сервера13:46:46 МСК. Она заменяет ранее подготовленную схему с общей кнопкой «Применить». Отдельный старый UX-пакет НЕ применять.

## Поведение

- Наличие находится в панели фильтров. Характеристики и наличие применяются автоматически с задержкой350мс; быстрые отметки объединяются, предыдущий запрос отменяется. Сортировка, статус и количество на странице обновляются сразу при изменении своего поля.
- AJAX получает обычную серверную HTML-страницу без X-Requested-With, чтобы не попасть в старый filterAction response. Обновляются контент каталога, заголовок, хлебные крошки, SEO-тексты, canonical и meta; header/cart остаются. Повторно включаются подгрузка товаров и слайдер рекомендаций. При сетевой ошибке — обычный переход по тому же URL.
- Адрес меняется через history.pushState. Назад/Вперёд загружают соответствующее состояние. На мобильном сохраняется открытая панель и блокировка фона; «К товарам» закрывает её. На компьютере нет видимых кнопок «Применить»/«Показать». Без JS есть обычная GET-форма с кнопкой.
- Группы без скроллов, первые6 вариантов и «Показать ещё»/«Свернуть». Выбранные варианты не скрываются. Общая прокрутка только у страницы на desktop; mobile — у содержимого bottom sheet.
- Наличие, sorting/status/page size принадлежат одной HTML-форме; внешние select связаны form=, поэтому работают и без JS.
- Для категорий24/48/96, старые25/50/100 отображаются как24/48/96. Все размеры делятся на1/2/3/4. Остальные типы листингов оставлены с прежними размерами через отдельный CatalogSelection::categoryState.
- Первичная порция12 карточек, lazy — остальные. Обе части кратны сетке3/4. Последняя страница может быть неполной по фактическому числу товаров.
- Stock на карточках приведён к уже свободному quantity из API; reserve повторно не вычитается. Модификации суммируются, минимум0. Live product_tpl.php изменён по двум точным арифметическим якорям с сохранением всех остальных серверных изменений.

## Посадочные

Одна однозначная группа может определять основную посадочную, дополнительные группы передаются параметрами. Уже открытая посадочная сохраняется, пока её единственный основной вариант выбран. OR в основной группе требует другой однозначной посадочной либо категории. Уточнённые комбинации noindex,follow, canonical на основную чистую посадочную. Одиночный выбор с настройками по умолчанию даёт чистый URL, default-параметры не добавляются. Прямой неоднозначный старый URL перенаправляется на подбор с обоими значениями. SEO-перенаправления сохраняют параметры.
