# Мобильный API чата Авито, v1

База: `https://its-center.ru/api/mobile/v1/avito/`. Только HTTPS. Один общий аккаунт Авито; каждый сотрудник входит под собственным email и паролем из админки. Требуются роль `admin`/`manager` и включённый доступ к чату в customers. Ключи Авито остаются на сервере.

## Вход и сессии

`POST login`, `Content-Type: application/json`:

```json
{"email":"manager@example.ru","password":"пароль","device_name":"iPhone Юрия"}
```

Ответ: `{"data":{"access_token":"64 hex символа","token_type":"Bearer","expires_at":1795000000,"user":{"id":1,"name":"Юрий","role":"manager"}}}`. Токен действует 30 суток, хранить в iOS Keychain / Android Keystore. Обновление токена — повторный вход, refresh-токена пока нет. Не передавать токен в URL, cookie, логи или аналитику. Сервер хранит только SHA-256 токена. Пароль хранить на телефоне не требуется.

Все остальные методы требуют `Authorization: Bearer <access_token>`. Cookie админки не даёт доступ к API. Для POST нужен JSON-объект (включая `{}` для выхода); только загрузка файлов использует multipart.

| Метод | Действие |
|---|---|
| GET me | Текущий сотрудник: id, name, role |
| GET sessions | Активные устройства: device_name, created_at, expires_at, current; секретов нет |
| POST logout | Удалить текущую сессию |
| POST logout-all | Удалить все мобильные сессии сотрудника |
| GET capabilities | Версия API, доступные операции, лимиты файлов, часовой пояс |

Каждый запрос проверяет актуальную роль и чекбокс доступа. Смена пароля делает прежние токены недействительными. Вход ограничен 10 попытками на email и 50 на IP за 15 минут (включая успешные), без доверия к клиентскому X-Forwarded-For.

## Операции чата

Ответ успеха всегда `{"data":...}`. Структуры Авито в списках/истории сохраняются, включая типы сообщений, content, created, direction. Неизвестные типы отображать как неподдерживаемое сообщение. `offset` от 0 до 100000. Страницы чатов по 50, сообщений по 100; следующая страница при полной предыдущей. Поиск по истории сервер пока не предоставляет.

| Метод | Параметры | Результат |
|---|---|---|
| GET chats | query: offset, unread=1 (необязательно) | chats; дополнительно is_unread, assigned_to |
| GET messages | query: chat, offset | История выбранного чата |
| GET unread | — | count, has_more; при has_more счётчик означает нижнюю границу |
| GET events | — | Локальная ревизия webhook; сравнивать revision |
| GET voice | query: voice_id | url для голосового, получать перед воспроизведением |
| GET check | — | Диагностика аккаунта/чата/истории |
| POST send | chat, text | Отправить текст, 1–1000 символов |
| POST read | chat | Отметить прочитанным |
| POST send-image | multipart: chat, image | Отправить JPG/PNG/GIF/BMP |
| POST upload-document | multipart: chat, document | Подготовить PDF/DOCX, вернуть token и ссылку |
| POST send-document | chat, token | Отправить подготовленную ссылку покупателю |
| POST revoke-document | chat, token | Отключить ссылку |
| GET workspace | query: chat | managers, assignee, notes, templates |
| POST assign | chat, manager (id, 0 — снять) | Назначить ответственного |
| POST note | chat, body (до 5000 символов) | Внутренняя заметка |
| POST template-save | id (0 — новый), title, body | Сохранить шаблон |
| POST template-delete | id | Скрыть шаблон |

Ответы, фото и документы отправляются реальным покупателям. Заметки остаются внутри системы. Шаблоны меняет автор или администратор. Документы передаются временной ссылкой на 7 дней, а не вложением Авито. Превью фото и прочие медиа приходят в content сообщений. Лимиты загрузки брать из capabilities; разрешение фото не больше 75 Мп.

Опрос events каждые 5 секунд при активном приложении; при изменении revision обновить список и открытый диалог. Резервный опрос истории каждые 15 секунд, счётчика — 30 секунд. При уходе в фон остановить опрос. Использовать задержку с увеличением интервала при 429/502. Часовые метки — Unix seconds; отображение Europe/Moscow. Открытие истории само по себе не помечает её прочитанной: отправить read после показа сообщений.

## Ошибки и повтор запросов

Формат: `{"error":{"code":"http_401","message":"..."}}`; ошибки полей/JSON имеют code `invalid_request`.

400 — запрос/поля; 401 — нужен вход; 403 — доступ отключён; 404 — неизвестный метод; 405 — неверный HTTP-метод (Allow); 413 — большой JSON; 415 — Content-Type; 429 — лимит входа (Retry-After); 502 — внутренняя/внешняя временная ошибка без раскрытия деталей. Ошибки лимита внешнего API Авито пока также возвращаются как 502.

Автоматически повторять можно чтение. Отправка не имеет ключа идемпотентности: после сетевого таймаута сначала обновить историю и проверить результат; не повторять отправку вслепую. Загрузка документа и отправка ссылки разделены, чтобы пользователь мог проверить файл перед отправкой.

## Развёртывание и проверки

Таблицы мобильных сессий/ограничений создаёт существующий `php8.2 bin/setup_avito_workspace.php` в деплое. Изменение Authorization в public/.htaccess нужно для передачи Bearer через Apache/FastCGI.

Проверки: `php tests/AvitoMobileAuthTest.php`, `node tests/AvitoMobileHttpTest.js` (PHP_BINARY при необходимости), существующие тесты AvitoMessenger/Media/Access/Workspace/UI. HTTP-тест работает с отдельной SQLite, не вызывает API Авито и не отправляет покупателям сообщения. Тестовый роутер требует AVITO_MOBILE_TEST_DB и находится вне public.

## Что ещё нужно для приложения

Этот этап создаёт серверный API. Клиент Android/iOS, push через FCM/APNs, обработка фоновых уведомлений, публикация в магазинах и подпись сборок ещё не реализованы. Без push уведомления доступны при активном приложении через polling. Следующие этапы: мобильный интерфейс и хранение токенов; затем регистрация устройств, отправка push из webhook и доставка при закрытом приложении; затем тестовые сборки и проверка на реальных устройствах.
